# 月面版 — すべてのフレームが月面の本物の影

[English](moon.md) | **日本語**

動画: [YouTube oe94IDXho9g](https://youtu.be/oe94IDXho9g) ・ フレームごとの結果: [`results/moon/frames.csv`](../results/moon/frames.csv)

Bad Apple!! の各フレームについて、実在の月面画像から光と影の相関（NCC）が最も高い場所を GPU で全探索し、
その場所を全解像度の画像から切り出して並べた動画です。黒い部分は本物の影で、各フレームは実在する
1か所を切り出し・拡大縮小・回転（一部は左右反転）・コントラスト調整しただけのものです。

出力は `output/moon/badapple-moon.mp4`（2560×1920、元動画と同じ 30000/1001 fps で音声と同期、
AV1 10bit・NVENC、元の音声付き）。左に 4:3 の月面、右の幅 480 px の列に ORIGINAL（元映像）・MAP・LOCAL を置きます。

- **MAP**：WAC 全球図。いま映っている範囲を黄色の枠（小さすぎる場合は最小サイズの枠と目印）で示し、
  それまでの範囲はすべてティールで残して件数を `VISITED` に表示します。
- **LOCAL**：映っている範囲の5倍（最小 20 km）を北が上の正射図法で表示した WAC の地図。範囲を実寸の枠で、
  その中の過去の範囲をティールで示します。
- **NCC グラフ**：再生済みフレームのスコアの履歴（再生位置より先は描きません）。画素の列ごとに最小〜最大を細い帯、
  直前1秒の平均を線で描き、現在の値を黄色の点で示します。
- **下部の情報欄**：座標、最寄りの IAU 地名、カメラ、朝・夕と現地の太陽高度、画像 ID と解像度、幅、回転、反転、NCC。
  すべての項目は固定の原点・ベースライン・等幅フォント・固定桁の書式で描くので、フレームごとに位置が揺れません。

## 実行

```powershell
./run-moon.ps1                 # data → frames → verify → search → refine → crops → encode
./run-moon.ps1 -Stage search   # 各工程は単独で再実行・再開できる
```

Windows、CUDA Toolkit（cuBLAS）付きの NVIDIA GPU、Visual Studio の C++ ツール、Rust、FFmpeg、`setup.ps1` で作る
`.venv` が必要です。CUDA の DLL は `sm_89`（RTX 40 系）向けで、他の GPU では環境変数 `CUDA_ARCH` を設定します。
`--size` で解像度を変えられます（4:3 以上の横長。例 `python -m badapple_moon encode --size 3840x2160`）。
月面は 1944×1458 で切り出し、表示の大きさに縮小して貼り付けます。

| 言語 | 担当 |
| --- | --- |
| Python + rasterio | カタログ・取り込み・切り出し・UI（[`badapple_moon/`](../badapple_moon)） |
| Rust + Rayon | フレーム抽出・探索ドライバ・CPU 検証（[`rust/moon-search/`](../rust/moon-search)） |
| CUDA C++ | ポーズの標本化・スコア・上位 k 件（[`cuda/moon/moon.cu`](../cuda/moon/moon.cu)） |

### データ

| ソース | 使い方 | パッチ幅 |
| --- | --- | --- |
| かぐや TC 単画像（USGS STAC、CC0） | 全 33,402 件の COG から 95 m/px 以下の内部オーバービューだけを範囲リクエストで取得（約 15 GB） | 2.4〜27 km（8 段） |
| かぐや TC ステレオ（TC1W/TC2W、USGS STAC、CC0） | 220,660 件。同じ方法で 3 つに分けて並列に取り込み（`ingest-tc --part k --parts 3`、約 78 GB） | 2.4〜27 km（8 段） |
| LROC WAC 全球モザイク 100 m | 1 ファイル（6 GB）を取得し、探索には 800 m に縮小 | 38〜434 km（8 段） |
| USGS Gazetteer of Planetary Nomenclature | IAU 承認済みの地名（`fetch-names`） | テロップ用 |

TC 画像の幾何は、画像中心の接平面（km）から全解像度画素への 2 次多項式として GDAL/PROJ 経由で当てはめています
（正距円筒・極ステレオとも同じ扱い、残差 0.25 画素以下）。WAC は正射図法の逆変換を厳密に計算するので、緯度帯ごとの
補正は不要で、極域も同じコードで扱えます。画素値は画像ごとの 1〜99 パーセンタイルを 1..255 へ伸長し、0 を欠損とします。
`qa-images` は、取り込んだ観測のうち 1〜99 パーセンタイルの幅が 250 DN 未満のもの（単画像 1,013 枚、ステレオ 2,365 枚）を探索から除外します。
信号の弱い露光で、伸長すると検出器の継ぎ目・縦縞・圧縮ブロックが目立つためです。

SP サポート系列（204,690 件）は使っていません。機上圧縮が強く、全解像度で切り出すと大きなブロックや縞が出るためです。
474 m の TC 全球オルソモザイクも、縞やブロック状の欠損がシルエットとの偽の一致を生むため不採用にしました。

### 探索

1. **クエリ**：`ffmpeg … -pix_fmt gray` の出力を Rust で直接読み、完全に同じフレームはハッシュで除去し、端数画素の重み付きで
   32×24（と 64×48）に面積平均します。模様のある各フレームはそのままと左右反転の 2 通りで使い、単色の 9 種類（標準偏差 2 未満）は別処理です。
2. **候補**：パッチ幅は 0.15·√2ᵏ km の段、ストライドは幅の 1/16、各位置で 16 方向（22.5° 刻み）。セル（幅の 1/32）より粗いデータしか
   ない段は、その画像では探索しません。クエリの左右反転と候補の回転で、そのまま・左右・上下・180° をすべて含みます。
3. **GPU**（[`moon.cu`](../cuda/moon/moon.cu)）：1 ブロックで 1 ポーズを処理します。32×24 の各セルを、セルの大きさに合うピラミッド段から
   双線形 4 点（2×2 超標本化）で平均し、平均 0・ノルム 1 に正規化して fp16 にします。欠損を含むポーズ、標準偏差 3 未満（平坦）のポーズ、
   セルの 10% 超が伸長の上限（255）に張り付いたポーズは無効にします。最後の条件は TC のセンサー飽和を「白いシルエット」として
   選ばないためのものです（この条件がないと画面の 40% 超が白飛びしたフレームが 387 種類、追加後は 7 種類）。
   cuBLAS の `GemmEx`（fp16 入力・fp32 累積）でスコア行列を作り、上位 32 件カーネル（厳密な基数選択とバイトニック併合）で各クエリのリストに
   マージします。ポーズは Rust/Rayon が別スレッドで生成してダブルバッファで GPU へ送り、5 分ごとにチェックポイントを書きます。
   ピラミッド込みで 53 GB になるため 14 GB 以下のシャード（`--shard-gb`）に分けて順に読み込みます。上位 32 件はシャードをまたいで引き継ぎ、
   1 回で処理した場合と同じスコアになります。
4. **再探索**：各クエリの上位 32 件から互いに離れた最大 12 か所を選び、位置・スケール・回転の 3⁴ 近傍を、刻みを半分にしながら 6 回探索します（fp32）。
   スケールは探索した段より 1 段小さい幅（TC は約 1.7 km）までで、データの解像度は下回りません。最良の 1 件を左右反転の 2 通りから選びます。
5. **単色フレーム**：同じ探索で集めた暗いリスト（平均・標準偏差が低い）と明るいリストから順に使います。
6. **検証**（`moon-search verify`）：Rust/Rayon の CPU 版と GPU の結果を照合します。
7. **統合**（`python -m badapple_moon merge`）：同じクエリの複数回の結果を合わせ、32×24 のスコアが最も高い候補を選びます。
   公開版は 4 回分を統合しています（95 m/px での 2.4 km の段と 3.4〜27 km の段、180 m/px でのステレオ追加後の探索、単画像だけの最初の探索）。
   大きな探索では良い候補が上位 32 件から押し出されることがあるためで、どのフレームも統合前のどの回よりスコアが下がりません。
   `run-moon.ps1` は最終的な設定での 1 回分を実行します。

### レンダリング

一致したポーズを同じ幾何で 1944×1458 へ逆写像し、全解像度の COG（出力画素に合うオーバービュー段から範囲読み込み）または
100 m の WAC から 3 次補間で取り出します。出力 1 画素が元画像の 1 画素より粗い場合だけ 2×2 で超標本化します。照合時と同じ反転・回転をかけます。
TC 画像内部に点在する欠損画素（−32768、64 画素以下）は補間の前に最寄りの有効値で埋めます。埋めないと 3 次補間のオーバーシュートで
影の中に小さな白い四角が出ます。

切り出しは全解像度の値で検査します。2,750 DN 以上（TC の飽和域）が 2% を超える場合、または欠損がある場合は、そのフレームの再探索で得た
次の候補に置き換え、`matches.json` の `qa.rejected` に記録します。ステレオ系列は露出設定が異なり飽和の値が画像ごとに違います
（約 2,850〜6,300 DN）。一律 2,750 DN の判定でこれらは確実に外れますが、明るいだけの正常な地表も一部外れます（安全側の判定です）。

黒点は「元画像全体の 1 パーセンタイル（取り込み時と同じ値）」と「切り出しの 1 パーセンタイル」の大きい方、白点は切り出しの
99.5 パーセンタイルで、元画像の範囲の 20% を下回らないようにして影の中のノイズを持ち上げないようにしています。
さらにガンマ 1.3 で、深い影の中に出るかぐや TC の機上圧縮のブロックを目立たなくしています。

地名は点を含む最小の地形、なければ縁までの距離が最も近い地形で、距離と直径を併記します。カメラ行の朝・夕と太陽高度は、
観測時刻の sub-solar 点（JPL Horizons、MOON_ME・東経正）から球面で計算します（[`sun.py`](../badapple_moon/sun.py)、
`cache/moon/subsolar.json` にキャッシュ）。STAC の `view:sun_elevation` は観測ごとの 1 つの値で、同じ軌道ではほぼ変わらず、その場所の
太陽高度ではありません（88.56°S で 6.0° でしたが実際は 0.45°）。Horizons の月面地点からの方位・高度と 0.01° 以内で一致することを
確認しています。太陽が地平線のわずかに下（最大 −3.6°）のフレームもあり、明暗境界のすぐ夜側で高い縁や山頂だけが照らされている場面です。

完成した動画のカメラ行だけを直すときは `python -m badapple_moon refooter` を使います（切り出しは不要）。古い文字列を同じ描画で作り、
デコードした帯と一致することを確認してから差し替え、AV1 で再エンコードします（音声はコピー）。

## 公開版の結果から作り直す

[`results/moon/matches.json`](../results/moon/matches.json) には、上の検査後に採用した全種類のフレームのポーズが入っているので、
探索をせずに動画を作り直せます。取り込むのは [`results/moon/rasters.txt`](../results/moon/rasters.txt) の 2,570 枚だけです。

```powershell
.venv\Scripts\python -m badapple_media fetch
.venv\Scripts\python -m badapple_moon fetch-names
.venv\Scripts\python -m badapple_moon catalog
.venv\Scripts\python -m badapple_moon catalog --series stereo
.venv\Scripts\python -m badapple_moon ingest-tc --ids results/moon/rasters.txt
.venv\Scripts\python -m badapple_moon ingest-tc --catalog cache/moon/tc_catalog_stereo.jsonl --output cache/moon/tiles-stereo-0 --ids results/moon/rasters.txt
.venv\Scripts\python -m badapple_moon fetch-wac
.venv\Scripts\python -m badapple_moon ingest-global
mkdir output/moon; copy results/moon/matches.json output/moon/matches.json
.venv\Scripts\python -m badapple_moon crops
.venv\Scripts\python -m badapple_moon encode
```

`crops` は読み込んだ matches ファイルに検査結果を書き戻すため、コピーしてから使います。フレーム 4077・5580（単画像系列）と 1135・5531（ステレオ系列）で確認したところ、
新たにダウンロードしたデータからこの手順で切り出した月面は、公開動画と 51〜55 dB の PSNR で一致しました（差は圧縮によるもの）。
